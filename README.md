# Testimony & Prayer Site

Real stories of what Jesus has done, prayer requests, and a clear next step for anyone who doesn't know Him yet.

The source of truth for vision, scope and decisions is the project brief (kept in the Claude project). This README covers how the code is built, tested and shipped.

## Layout

| Path | What it is |
| --- | --- |
| `web/` | React + TypeScript + Vite + Tailwind site (`/`, `/stories/:slug`, `/know-jesus`) |
| `api/` | Azure Functions v4 (Node 22), deployed as **SWA managed functions** |
| `shared/` | API contract types, display-name/excerpt helpers, categories + sample data |
| `db/` | Versioned SQL migrations, migration runner, dev sample seeding, API DB user setup |
| `infra/` | Bicep for one environment + `bootstrap.sh` for the one-time Azure/GitHub identity setup |
| `e2e/` | Playwright tests (run locally, against PR previews, and as the post-deploy smoke test) |

## Local development

Requires Node 22.

```bash
npm install
npm run dev          # web on :5173, API on :7071 with in-memory sample data
```

No Azure, database or Functions Core Tools needed for day-to-day work. The local API (`api/src/local/server.ts`) serves the same handlers as the Functions app.

```bash
npm run lint && npm run typecheck && npm test   # what CI runs first
npx playwright test                              # e2e against a local build
npm run test:db                                  # needs a SQL Server (see CI's db-integration job)
```

## Pipeline

**Every PR (`ci.yml`)**
1. Format, lint, typecheck, unit tests, build, Bicep build.
2. Migrations + SQL repository tests against a disposable SQL Server container.
3. Playwright e2e against a local build with sample data.
4. *(Azure enabled)* Bicep what-if, deploy a full web + API preview environment, Playwright e2e against it. The preview closes when the PR closes.

**Merge to main (`deploy.yml`, dev)**
Bicep → open SQL firewall for the runner → migrate → seed samples (dev only) → ensure API DB user → close firewall → app settings → deploy → wait for `/api/health` → smoke test.

## Azure setup (once per environment)

```bash
az login && gh auth login
./infra/bootstrap.sh dev "<subscription>"
gh variable set AZURE_ENABLED --repo mattalagala/testimony-site --body true
```

This creates the resource group, an Entra app registration with a GitHub OIDC federated credential (no secrets), RG-scoped RBAC, the SQL Entra admin group (you + the pipeline), and the GitHub `dev` environment variables. Everything else is deployed by the pipeline.

## Data & privacy rules baked into the code

- Public endpoints only return **approved, already-published** content. One filter (`PUBLIC_FILTER` in `api/src/data/sql-repository.ts`) enforces this, and tests cover pending/rejected/needs-care/future rows.
- Public DTOs (`shared/src/index.ts`) carry no email, submitter id, token or moderation detail. A test asserts the exact public fields.
- Story bodies are rendered as plain text, never HTML.
- Sample testimonies are labelled as samples and the seeder refuses to run in prod.
- The API connects to SQL as `api_app` (`db_datareader` + `db_datawriter` only). Its password is generated by the pipeline and lives only in SWA app settings.
